Guidance for AI coding agents working in this repository — any vendor.

## What this repo is

**blyant records** (`codeberg.org/blyant/records`) — a publish-your-conversations site: Markdown transcripts in `records/` are built by Hugo through `bin/build.sh` (the one build path) and published to Codeberg Pages by default (`https://<owner>.codeberg.page/<repo>/`), to GitHub/GitLab Pages via shipped shims, or to any pages branch/webroot via `records publish`. Forks publish their own site with zero edits — owner/repo/URL are derived per fork by `bin/build.sh` from CI env; an uncommented `baseURL` in `tools/hugo/hugo.yaml` beats all derivation (custom domains, VPS). See **Publishing** under Architecture and `docs/publish.md`.

## Skills portability

The skills follow the [Agent Skills](https://agentskills.io) SKILL.md format, discovered via root symlinks (`.claude/skills` for Claude Code, `.agents/skills` for Codex, Mistral Vibe and other `.agents/` readers; a tool with another path gets another symlink, never a copy). For non-Claude agents:

- Frontmatter beyond `name`/`description` (`model`, `effort`, `disable-model-invocation`, `argument-hint`) is Claude Code-specific — ignore keys you don't support.
- `` !`command` `` in skill bodies is Claude Code shell injection. If your runtime doesn't preprocess it: run the command and substitute its output at that point before following the instructions.
- `allowed-tools` uses Claude Code's pattern syntax; treat it as advisory pre-approval, not a loading requirement.

When appending to records directly (no skill): `## Human` / `## Assistant` turns with exactly one blank line between blocks; assistant turns end with a signature line `— <model name>` (em-dash — the site strips these at render time); frontmatter `date:` is local-offset ISO seconds (e.g. `2026-08-13T15:29:00+02:00`), never UTC-normalized; omit `title:` unless the user names one.

## Architecture

**Config layering.** Theme defaults live in `tools/hugo/themes/Fuglekasse/hugo.toml` `[params]`; the site's `hugo.yaml` `params:` deep-merges over them (site wins); `HUGO_PARAMS_*` env vars override both (CI uses `HUGO_PARAMS_REPOURL`). New theme options must follow this pattern: default in theme toml, read via `site.Params.*`, documented in the theme README and as a commented example in `hugo.yaml`.

**Rendering pipeline.** Records are `## Human` / `## Assistant` turns with assistant signature lines (`— model-name`). `layouts/_partials/record.html` takes a dict `{content, prefix?, voice?}` (`content` = rendered `.Content`/`.Summary`; `voice` = the page's `voiceRecorded` frontmatter, passed by all four dict-callers — when true an inline mic SVG (`span.voice-icon`, self-contained stroke attrs) is appended to each Human heading before the `#` anchor; `book.lua` mirrors it on `h6.speaker` Human labels via `isTrue(r.meta.voiceRecorded)`, CSS in `baseof.html`/`pdf.css`/`epub.css`) and: strips signatures, rewrites relative `records/` links to forge raw URLs (shape per `params.repoLinkStyle`/`repoBranch` via `_partials/repo-link.html` — see **Forge links**), and wraps each turn in `<section class="user|assistant">` for styling (the human-turn regex also matches the legacy `## User` heading, so older records still render; both map to `class="user"`). Each Human turn keeps its Goldmark heading id and gets a trailing hover `#` anchor (`<a class="anchor">`); the optional `prefix` namespaces those ids (`<prefix>-human-N`) so they stay unique when many records share one page — callers pass the record's URL slug (`path.Base .RelPermalink`) in single/single-flowing/posts modes and no prefix on standalone record pages (`page.html`). Assistant headings still drop their id. All record display — single pages (`page.html`), the posts-mode excerpts, and the single-mode cards and single-flowing articles (`home.html`) — must go through this partial.

**Assistant blocks.** A fenced code block marked ```` ```assistant ```` (model output pasted into a record) is not shown as code: `layouts/_markup/render-codeblock-assistant.html` — the first markup render hook in either theme, a byte-identical copy in both — renders `.Inner` through `.Page.RenderString` and wraps it in `<div class="assistant-block">` behind a `<p class="assistant-label">Assistant</p>`. The hook strips ids from the rendered headings (`replaceRE` on `<h[1-6] id="…">`): `record.html` splits turns on `<h2 id="human|assistant">`, so a heading inside the block would otherwise fake a turn boundary, and the ids would collide across records on the one-page modes. CSS (both themes, beside the `blockquote` rules) gives the panel a **fixed fill per scheme** — `--ab-bg: #717484` in light, `#2a2b38` in dark (a faint lift off `--bg`) — while everything else comes from the **dark** half of `params.style`: `--ab-fg` (text and, in light mode, the near-white label) and `--ab-code` (`$s.dark.bg`, dropping to `$s.dark.surface` under `prefers-color-scheme: dark` so nested code/quotes/even rows don't blend into the darker fill), plus a re-declaration of the seven `--hl-*` vars at their Dracula values, so a nested fence stays readable. In dark mode the label is a `color-mix` light grey. Headings sit one step below their counterparts outside the panel. The turn-heading rules were narrowed to `section.user > h2` / `section.assistant > h2` in the same pass so they stop reaching into nested content. `book.lua` mirrors it: a `CodeBlock` handler in `contentFilter` re-reads `cb.text .. "\n"` (without the newline `pandoc.read` drops a final table row) as gfm, walks it through `contentFilter` again, and returns a `Div.assistant-block` led by `Header 6 .speaker.assistant-label`; the injected `header-includes` `:root` gained `--ab-*` — the fill from the literal `abBg` (the light-scheme value, since the book prints the light palette), the rest from `style.dark`. `pdf.css` paints the same panel (plus Dracula overrides for skylighting's `span.kw`-style tokens), `epub.css` keeps it structural (bordered box, no colour) and `booklet.css` prints it as an outlined white box.

**pageMode.** `params.pageMode` switches the home page: `basic` (link index, default), `posts` (latest `postsCount` excerpts with Read-more), `single` (one-page site: `_index.md` card first, then every record as a document card ordered by `params.singleOrder` with `featured: true` records pinned first; no auto links to records), `single-flowing` (one continuous conversation: `.Content` intro plain, then every record's turns via `record.html` inside `<article class="record-flow" id="<slug>">` — no titles/tags/dates, chapters flattened into one date-ordered stream per `singleOrder` (featured records pinned first), records separated by a dimmed centred `<div class="record-sep">· · ·</div>` dinkus; `.record-sep` CSS in `baseof.html`, mirrored in `pdf.css`/`epub.css`). In single mode each record card's `.record-head` title carries `id="{{ path.Base .RelPermalink }}"` (the record's URL slug, site-unique) plus a trailing `<a class="anchor" href="#…">#</a>`; the `#` is hidden (`opacity:0`) and fades in on `.record-head:hover` or anchor `:focus`, with `scroll-margin-top` on the heading — CSS in `baseof.html`. **Featured styling:** a `featured: true` record's `<article>` gains a `featured` class in both render spots, and two rules (Fuglekasse `baseof.html`, Postkasse `postkasse.css`) tint it one nuance of accent off the surface it sits on — `.mode-single .record-page.featured` mixes from `--card` (a tinted card among plain cards), `.record-flow.featured` from `--bg` plus `border-radius`/`padding` (a soft panel in the bare stream). Both use `color-mix(in srgb, <base> 92%, var(--accent))`, so fork palettes and light/dark follow automatically; unprefixed `.record-flow` is safe because that class exists only in flowing mode. `home.html` warns and falls back to basic on unknown `pageMode` (reassigning `$mode`, so the fallback renders exactly as basic, chapters included), and warns + falls back to `asc` on unknown `singleOrder`; `baseof.html` tags `<main class="mode-…">` for the CSS (the raw param value, so `mode-single-flowing` never matches the `main.mode-single` JS selector).

**One-page output.** In `single` and `single-flowing` every record already renders on the front page, so those modes publish **only** `index.html` — no per-record pages, no `sitemap.xml`. Hugo config cannot branch on its own params, so the rules live in a second config, `tools/hugo/one-page.yaml`, merged by `bin/build.sh`: it reads `pageMode` (`HUGO_PARAMS_PAGEMODE` env wins over the `sed`-grepped `hugo.yaml` value) and passes `--config hugo.yaml,one-page.yaml` for those two values, plain `--config hugo.yaml` otherwise (byte-identical to the default config lookup — verified). The overlay is a `cascade` whose catch-all `target: {kind: page}` sets `build: {render: link}` — `link`, never `never`: `never` empties `.RelPermalink`, which every single-mode anchor id, `threeDotAnchor` seed and TOC target is derived from — plus `disableKinds: [taxonomy, term, rss, sitemap]`. **List keys replace (not merge) across config files**, so the overlay restates `hugo.yaml`'s `cascade` and `disableKinds` in full; both keys carry a `MIRRORED in one-page.yaml` comment (an overlay stating only `disableKinds: [sitemap]` brings RSS back — the leak the project deliberately disables). Order matters inside `cascade`: **first match wins**, so an exemption entry (`path: '{/license}'`, `render: always`) must precede the catch-all — the footer links to the license page. `404.md` needs no exemption: its own front-matter `build:` block beats the cascade, which is also the documented per-page escape (`build: {render: always}`). What still ships: `index.html`, `404.html`, `license/index.html`, `static/`, the books, and record-bundle attachments — page *resources* publish under `render: link` even though the bundle's `index.html` does not, so `/<slug>/photo.png` stays reachable (the front-page relative-link 404 was kiste 6, fixed in Postkasse's render hooks 2026-08-31; Fuglekasse still 404s there). No opt-out param by design; a hand-run `hugo`/`hugo server` skips the merge, so dev previews still write record pages.

**bookLook.** `params.bookLook` (theme default `false`; honoured in single-flowing only — other modes `warnf` and ignore it) makes three root-level `records/` files special: `forside.md` (front cover — rendered first and standing in for the `_index.md` intro, which is skipped when forside exists), `side-1.md` (page 1, second) and `bakside.md` (back cover, always last); each is optional, and same-named files in tag/chapter folders stay ordinary records. `home.html` extracts them from `$loose` and builds `$flow` (forside, side-1, featured then dated records per `singleOrder`, bakside) — the single source of order for both the flowing stream and the flowing TOC (the TOC guard is now `(or $loose $chapters $flow)`); specials render like other flow records but with an extra `book-forside`/`book-side-1`/`book-bakside` class on their `<article class="record-flow">`. `book.lua` mirrors it when `flowing`: specials are captured before the loose/chapter partition, wrapped in `Div` class `record book-<name>` with no `· · ·` separator adjacent (dinkuses stay between dated records only), the `_index` intro is skipped and the generated `include-before` cover dropped when forside exists (forside *is* the cover); `pdf.css`/`epub.css` give `.book-forside`/`.book-side-1` `page-break-after: always` and `.book-bakside` `page-break-before: always`. Give the special files a `title:` — the flowing TOC shows it. **Sunken dividers:** inside `side-1` and `bakside` only, a Goldmark thematic break (`---` with a blank line above — directly under text it is a setext `<h2>`, not an `<hr>`) renders as an inset trough: `.book-side-1 hr, .book-bakside hr` in `baseof.html` + `postkasse.css` set `height: 1.65em; height: 1lh` (the `em` value is the fallback older engines keep when they drop the invalid `1lh`), `border: 0`, `border-radius: 5px`, `background: color-mix(in srgb, var(--bg) 92%, #000)` (derived from the page bg so it darkens in any fork palette — `--surface` would invert, being lighter than `--bg` in light mode and darker in dark mode) and a two-part `box-shadow`: `inset 0 2px 4px rgb(0 0 0 / .30)` for the recess plus `inset 0 -1px 0 rgb(255 255 255 / .09)` as the near lip. Web-only and scoped — `forside`, records and the PDF/EPUB/booklet keep the default rule.

**threeDotAnchor.** `params.threeDotAnchor` (theme default `false`; honoured in single-flowing only — other modes `warnf` and ignore it) turns the `· · ·` `record-sep` dinkus into a clickable `<a class="record-sep" href="#<id>" id="<id>" aria-label="Link to this point">`, and — unlike the default `{{ if $i }}` separator — emits one **above every record including the first** (so the top post is anchorable), the only skip being bookLook specials — no dinkus sits above `forside`, `side-1` or `bakside` (`{{ if not $isSpecial }}`), mirroring `book.lua`, where separators fall between dated records only. The `<id>` is 5 chars from the 66-char URL-safe alphabet `A-Z a-z 0-9 - . _ ~` (`66⁵ ≈ 1.25e9`), derived deterministically in `home.html`: `hash.FNV32a (path.Base $r.RelPermalink)` → base-66 via a 5-iteration `mod`/`int (div …)` loop over the alphabet string, so ids are stable across builds (Hugo has no build-time RNG) and collide only on a slug-hash collision. The loop hoists `$isSpecial` (previously inline for the `book-*` class) once and reuses it. CSS: `.record-sep` gains `display:block; text-decoration:none`, `a.record-sep { cursor:pointer }` and `a.record-sep:target { color: var(--accent) }` in `baseof.html` + `postkasse.css`. When the param is off, the `else if and $i (not $isSpecial)` branch emits the plain `<div>` between records, skipping bookLook specials the same way (identical to the pre-bookLook output when `bookLook` is off). Web-only — `book.lua`/PDF/EPUB untouched.

**showTimeEarlier.** `params.showTimeEarlier` (**Postkasse only** on the web — Fuglekasse stays fenced and ships no default; honoured in single-flowing only, other modes `warnf` and ignore it via the stickyNav clamp idiom) labels each record with the distance back from the newest one: `<div class="time-earlier">3 days earlier</div>` emitted **inside** `<article class="record-flow">` as its first child (right after the optional `permalink.html` call), floated to the record's top-right corner — it is a property of the record, not of the `· · ·` separator, so both sep branches are label-free and a record without a separator (the first in the stream with `threeDotAnchor` off) still gets one. The "now" anchor is `index (sort $loose "Date" "desc") 0` computed over the **post-bookLook-extraction** `$loose`, so a `bakside.md` dated later than every record can never anchor; the anchor **labels itself with its own date** rather than a gap — `<div class="time-earlier time-now"><time datetime="2006-01-02">…</time></div>`, formatted with `params.dateTitleFormat` (`or` fallback `"2006-01-02"`) — while bookLook specials get no label at all. The gap phrase comes from the value-returning `inline/time-earlier.html` partial fed `sub $anchor.Date.Unix $r.Date.Unix`: minutes under an hour (clamped to ≥ 1, so a sub-minute gap reads "1 minute earlier"), hours under a day, days under 30, then `N months[ and M days]`, then `N years[ and M months]` — the "and" half dropped at 0 via `with mod …`, plurals via `cond (eq $n 1)`. Deliberate approximations: 30-day months, 12-month years. `book.lua` mirrors both halves, inserting the `Div.time-earlier` at index 1 of the record's blocks (`timeEarlier()` + `naiveSecs()`, a days-from-civil conversion rather than `os.time` so the build machine's zone never leaks in; the anchor's date via the existing `goFormat`/`dateTitleFormat`; dates stay naive literals, so a mixed-UTC-offset corpus can differ from the web by an hour at a tier boundary — accepted). `book.lua` reads the site config only (theme-toml defaults are invisible to it, as with `demoMode`), so the books label their records only when `hugo.yaml` sets the param — and because `book.lua` is theme-independent, a **Fuglekasse** site that sets it gets book labels but no web labels. The two implementations are a checked pair — change `inline/time-earlier.html` and `timeEarlier()` together. CSS `.time-earlier` is a `float: right` rule in `postkasse.css`/`pdf.css`/`epub.css` (it shares the top line with a floated `.permalink`, which floats first and so sits rightmost); `.time-now` carries no rule of its own and exists as a fork styling seam; `booklet.css` inherits pdf.css.

**demoMode.** `params.demoMode` (theme default `false`; the site sets `true`) renders theme-shipped demo records — content files with `demo: true` front matter; the theme ships `content/example/example-recording.md`, merged via Hugo's default theme-content union like `content/404.md` — only while the site has no real records: gated once in `home.html` right after the `$all` chokepoint (`$real := where $all "Params.demo" "!=" true`; `$all` keeps the demo set only when demoMode is on and `$real` is empty), so every mode, chapters, TOC and filter follow. Auto-hide means zero-edit forks inherit `demoMode: true` safely — their first record hides the demo. The theme's `content/_index.md` (welcome front page) is deliberately not demo-gated: a site `records/_index.md` shadows it, like the 404 page. Limitations by design: hidden demo pages keep their direct URLs and sitemap entries (unlisted only), and demo content never reaches the PDF/EPUB/booklet (`book.lua`/`build.sh` read `records/` from disk and the site config only — a theme-toml `demoMode` default is invisible to them too). `demo` is a reserved front-matter key.

**Chapters.** A first-level `records/` folder named as a number — arabic (`^-?\d+$`) or strict roman numeral (case-insensitive) — groups its records under `<details class="chapter"><summary>folder-name</summary>` (the `open` attribute is now conditional — see below) in single and basic modes only (posts stays flat; single-flowing skips the grouping entirely, so every record lands in `$loose`). Loose records (root or tag folders) render first; chapters follow always-ascending, arabic block before roman, with featured-then-`singleOrder` (single) / featured-then-newest (basic) ordering only the records inside each chapter. Grouping is by `.Section` in `home.html`, which factors the shared card/link markup into inline partials (`inline/record-card.html`, `inline/record-list.html`, and `inline/record-title.html` — the display-title helper: hand-written `.Title` else the timestamp slug via `dateTitleFormat`, wrapped in `<time>`, whitespace-trimmed, reused by cards, the basic list, posts excerpts, and the TOC); `summary` CSS sits in `baseof.html`. The `<summary>` shows `folder-name — title` when the chapter carries an optional `records/<n>/_index.md` section page with a `title:`: `home.html` reads it via `site.GetPage`, guarded by `.File` (the `_index.md` exists) and a case-insensitive `.Title`≠name compare (drops Hugo's humanised default, so an untitled `_index.md` still shows just the number); the section page never becomes a record (`site.RegularPages` excludes it, `cascade` keeps `render/list: never`). Each `<summary>` carries `id="chapter-<name>"` and a trailing hover `#` anchor (`.anchor`, sharing the record-head CSS in `baseof.html`); a small `baseof.html` listener calls `stopPropagation` on that anchor's click so linking to a chapter doesn't toggle its fold. Empty folders are invisible (git doesn't track them); word-folders that parse as roman (`cd`, `mix`, `ml`) become chapters — documented caveat in the theme README.

`params.chapterState` (theme default `"latest"`; `home.html` `warnf`s + falls back to `"latest"` on an unknown value) sets each chapter's fold state: `"latest"` opens only the chapter whose name matches the newest record's `.Section` (`$latestSection` = the `.Section` of `index (sort $all "Date" "desc") 0`, guarded by non-empty `$all`; a loose/tag newest record opens no chapter), `"expanded"` opens all, `"collapsed"` opens none. A chapter's `records/<n>/_index.md` overrides the global setting with `chapterOpen: true|false` — read in the same `site.GetPage` block as `title` via `isset .Params "chapteropen"` (Hugo lowercases the key; `isset` keeps `false` distinct from unset) and always winning over `chapterState`. `home.html` resolves the boolean per chapter before the arabic/roman branch, stores it as the dict's `open` key, and both render loops emit `<details class="chapter"{{ if .open }} open{{ end }}>`.

**Table of contents.** `params.showToc` (theme default `false`, opt-in) renders a floating TOC — rendered inline in `home.html` from the same `$loose`/`$chapters` data, guarded by `and site.Params.showToc (ne $mode "posts") (or $loose $chapters $flow)`, so it shows on the home page in every mode but posts (in single-flowing it's a flat list in `$flow` order — chapters are flattened, bookLook specials in place — and the only place record titles appear). Markup is nested `<details>` (no JS for the fold): an outer `<details class="toc">` (a fixed top-right button, SVG list icon, marker hidden) whose panel lists loose records (`ul.toc-loose`) then each chapter as a `<details class="toc-chapter">` that reveals its records; TOC chapters always start collapsed regardless of `chapterState`. Link targets switch on mode — single/single-flowing → in-page anchors (`#<slug>`, matching `.record-head` ids in single and `article.record-flow` ids in flowing), basic → `.RelPermalink`; sort is featured-first then `singleOrder` in single/single-flowing, featured-first then newest in basic — mirroring each mode's body order. Classes `toc`/`toc-chapter` are kept distinct from `chapter` so the scroll-to-top JS (`details.chapter > summary`) is unaffected. CSS sits with the other fixed-element styles in `baseof.html` (clears the bottom-corner logo + scroll button). A `baseof.html` `revealHashTarget` handler (on `hashchange` + load) opens any collapsed `<details>` ancestor of the hash target and re-scrolls, so single-mode TOC links and the chapter `#` anchors reveal records inside collapsed chapters. A document-level click listener closes the open `<details class="toc">` when the click lands outside it (`!toc.contains(e.target)`).

**Filter.** `params.showFilter` (theme default `false`, opt-in; honoured in single mode only — other modes `warnf` and ignore it) renders a client-side record filter on the single home page: a fixed funnel button bottom-left (`details.filter`; class `beside-spotify` shifts it to `left: 2.75rem` when `params.spotify` is set, else it takes Spotify's `left: 1rem` spot) whose panel opens upward like the Spotify player. `home.html` renders it via the inline partial `inline/filter.html` fed `$all`, which builds sorted/deduped tag and language vocabularies at template time — the language fieldset only renders when some record sets `language:`, with a `(none)` checkbox when some record doesn't — plus always-present from/to date inputs, a `Word` search input (last group, nearest the button) and a Clear button (no submit; no-JS leaves a plain `<details>` with inert controls). Cards carry the machine-readable state: `inline/record-card.html` emits unconditional `data-date="YYYY-MM-DD"` (also the intro discriminator — the `_index` card has none, so the JS selector `article.record-page[data-date]` never touches it) and `data-tags="a,b"` (independent of `showTags`); language reuses the `lang` attribute (absent = the `none` bucket; comma-in-tag unsupported). The JS sits in the `baseof.html` IIFE, gated on `details.filter` existing: groups (tags, languages, date range, word) AND together, tags/languages match-any, dates inclusive by lexicographic compare on `data-date`, word compiled as a case-insensitive regex (invalid syntax regex-escaped to a literal) and tested against the card's whitespace-collapsed `textContent`, cached once as a `wordText` expando; the word input re-filters live on `input` (`change` alone fires only on blur/Enter), and matches in visible cards get an accent tint via the Custom Highlight API (`::highlight(word-match)` rule in `baseof.html`; browsers without the API filter untinted); non-matching cards get `.filter-hidden` (`display: none`), chapters with no visible card hide too, chapters with matches force-open while a filter is active (pre-filter fold remembered once in `dataset.filterOpen`, restored on clear). State syncs two-way with the URL — `?tags=a,b&language=nb,none&from=…&to=…&word=…`, parsed via `URLSearchParams` on load (prefills the controls), written back hand-serialized (commas literal, `word` `encodeURIComponent`ed) via `history.replaceState` with the hash preserved; cleared groups drop their params. The popper joins the click-outside close list; `revealHashTarget` is untouched — filter wins, a hash to a filtered-out card just doesn't scroll. `book.lua`/PDF/EPUB are untouched (view-only feature).

**Comment links.** `params.commentURL` (theme default unset/commented) points at a forge new-issue endpoint and renders a per-record `Comment` link (a `.post-date`-styled `<p>`) via `_partials/comment-link.html` — called from `page.html` and the single-mode `inline/record-card.html`, after the date line. The link href is `<commentURL>?title=[<site> - #<slug>]: ` (`querify`-encoded); `<site>` is `params.commentSite` else the `baseURL` host (`urls.Parse`), `<slug>` is `path.Base .RelPermalink`. `LICENSE.md` is skipped inside the partial (it renders through `page.html`; other render spots only see records). Not rendered in posts/basic/single-flowing, never in the PDF/EPUB. This exists so forks like tb4-rot don't need site-level `layouts/` overrides for their Comment links — overrides shadow the theme wholesale and go stale (the cause of the "filter didn't show up on i.xil.no" bug, 2026-07-28).

**Head extras.** `_partials/head-extra.html` (both themes) is an empty comment-only partial called from `baseof.html` just before `</head>` — the seam for a fork's JSON-LD, extra meta tags or verification tokens. It exists for the same reason as `comment-link.html`: a site-level `layouts/baseof.html` shadows the theme's copy wholesale, so every later head/palette/CSS change silently stops reaching that site (the assistant-feelings.com "featured tint didn't show up" bug, 2026-08-14 — its override had drifted by exactly the three new CSS lines). Overriding the partial instead keeps the site's delta to its own markup. Empty by default, so adding the call left both themes' output byte-identical (verified with `--minify`).

**PDF book.** `params.pdf` (theme default unset/commented; commented site example `pdf: blyant.pdf`) names a PDF at the site root and puts a footer `Get PDF` link (`relURL`) in `baseof.html`; unset shows no link and skips the build. The book build now runs inside `bin/build.sh` right after Hugo (`tools/pandoc/build.sh` self-gates on the params and exits 0 when all are unset; `bin/build.sh` additionally skip-notes when pandoc/weasyprint are absent, so stock GitHub/GitLab runners pass) — pandoc, WeasyPrint and DejaVu are baked into the hugo-runner image (Alpine: pandoc 3.6.4, weasyprint 64.1; local pandoc is 3.1.11.1) — the PDF ships with the site (on the canonical `tb4/pages` instance the site root is the domain root, so it serves at `https://tb4.codeberg.page/tb4.pdf`). `build.sh` greps `pdf:`/`epub:`/`booklet:`/`pageMode:`/`contentDir:` from `tools/hugo/hugo.yaml` (env overrides `SITE_CONFIG`/`RECORDS_DIR` for testing), then: `pandoc lua tools/pandoc/book.lua` → JSON AST → `pandoc -f json -s --toc --toc-depth=2 -c pdf.css --highlight-style highlight.theme` → HTML → `weasyprint` → PDF. `book.lua` mirrors the site: reads the config as pandoc YAML metadata (`markdown-smart`, so values stay literal; `ignoreFiles` regexes are re-read raw from the config text and matched via a documented simple-regex subset), walks the records dir, skips drafts/`404`/`_index`/ignored files (a root `records/LICENSE.md` is instead appended as back matter — see **Content conventions**), orders loose-then-chapters (arabic asc before roman asc, strict-roman by canonical round-trip; records per `singleOrder`, date from `date:` else filename timestamp), strips `— model` signature paras, splits level-2 `Human`/`User`/`Assistant` headings into `user`/`assistant` divs (pandoc may emit them as `<section>`, so `pdf.css` selects by class) with `h6.speaker` labels, demotes content headings by 2 and clears their ids (TOC depth 2 = chapters + records only), resolves relative images (record dir → records root → site/theme `static/`, raw-HTML `src=` included) and rewrites relative `records/` links to `<repoURL>` raw URLs per `repoLinkStyle`/`repoBranch` (env `HUGO_PARAMS_REPOURL` wins, as in CI — see **Forge links**). Record display titles follow `inline/record-title.html` logic with a Go-layout formatter subset (`2006 06 January Jan 01 1 Monday Mon 02 2 15 03 3 04 4 05 5 PM pm`); `dateTitleFormat`, `datePostFormat`, `showTags`/`showDate`, chapter `_index.md` titles all honoured. Meta: `pagetitle` (PDF title), `include-before` (cover: `greeting` in the `style.font` woff2 + site title + date — precedes the pandoc TOC), `header-includes` (`:root` palette + `@page` background from `params.style.light`, `@font-face` from `style.fontfile`), so fork palettes carry into the PDF. `pdf.css` mirrors `baseof.html` (light values as `var()` defaults) plus book chrome: A4 `@page` with bottom-centre page counter (none on the cover), `page-break-before` on `h1.chapter`/`h2.record-head` (book flow: each chapter/record on a fresh page), `nav#TOC a::after { leader(". ") target-counter(...) }` dot-fill page numbers (`leader()` needs weasyprint ≥ 61 — CI ships 64.1). `highlight.theme` holds the site's `--hl-*` light colours as a skylighting theme (like the site, it stays fixed when palettes change). With `pageMode: single-flowing` the book mirrors the site's flowing layout: `book.lua` reads `params.pageMode` and flattens chapters into the loose list, skips the `h2.record-head`/`post-tags`/`post-date`/chapter-`h1` blocks and inserts a native `Div.record-sep` (`· · ·`) between records (cover kept — unless bookLook supplies a forside, see **bookLook**); `build.sh` drops `--toc --toc-depth=2` from the PDF call (no Contents page, and no per-record page breaks since the `page-break-before` selectors never match — except the license back-matter heading, which keeps its `record-head` class in flowing too and so opens on a fresh page). Known noise: three ignorable WeasyPrint warnings from pandoc's built-in highlighting CSS (`gap: min()`, `overflow-x`, `user-select`).

**EPUB book.** `params.epub` (theme default unset/commented; commented site example `epub: blyant.epub`) works exactly like `params.pdf`: footer `Get EPUB` link in `baseof.html`, built by the same workflow step and `build.sh`, served from the site root. `build.sh` runs `book.lua` once and reuses `book.json` for both outputs; the EPUB is pandoc-direct (no WeasyPrint): `pandoc -f json --lua-filter epub.lua --toc --toc-depth=2 --split-level=2 -c epub.css --highlight-style highlight.theme` — `epub.lua` re-reads raw HTML nodes as native elements (chapters are XHTML; verbatim `<br>`/`<img>` from `unsafe: true` records would break well-formedness), split at h2 so each record (`h2.record-head`) gets its own chapter file, `-M title=<site title>` supplies the dc:title (`book.lua` only sets `pagetitle`), and `-M header-includes=` clears the PDF-only palette/`@font-face` style block (pandoc's epub3 template would otherwise embed it with a broken absolute font path). `epub.css` is structural only — e-readers override fonts and render grayscale, so turns/quotes/code are marked by borders, indentation and small-caps, no colours or font sizes in absolute units; fork palettes deliberately do not carry into the EPUB. With `pageMode: single-flowing`, `build.sh` drops `--toc --toc-depth=2 --split-level=2`, so the EPUB is one continuous chapter file with `· · ·` dividers (same flowing assembly from `book.lua`). Any of the three book params works alone; all unset = build.sh exits 0.

**Booklet.** `params.booklet` (theme default unset/commented; commented example `booklet: blyant-booklet.pdf`) works like `params.pdf`: footer `Get booklet` link in `baseof.html`, built by the same workflow step and `build.sh`, served from the site root. It is the PDF book re-rendered for duplex printing at 4 pages per sheet: pandoc runs again on the same `book.json` with `-c pdf.css -c booklet.css` (`booklet.css` overrides geometry — `@page` A5, `12mm 10mm 14mm` margins, `html { font-size: 9pt }` — and forces a white `#fff` page/html/body background for paper printing, `!important` on the `@page` one so it beats the site-palette `@page` bg from `header-includes`; other palette colours and TOC behaviour stay identical, `TOC_ARGS` shared so single-flowing drops the TOC here too), WeasyPrint prints an A5 PDF, and `tools/pandoc/impose.py` (pypdf) places the A5 pages two-up on A4 landscape sheets (`842×595pt`, each page scaled ~0.3% to exactly half a sheet) in booklet folding order — sheet k front `[n-2k, 2k+1]`, back `[2k+2, n-2k-1]` — so the duplex-printed stack (flip on **short** edge) folds in half into an A5 booklet. The page count is padded to a multiple of 4 with pypdf-blank pages (white, matching the page background; `impose.py` still takes an optional filler PDF as third arg). With **bookLook** (single-flowing only) the booklet folds like a real book: `booklet.css` gives `.book-forside`/`.book-side-1` `page-break-after: right` (WeasyPrint inserts a blank verso, so side-1 and the first record open recto) and suppresses the page counter on those blanks via `@page :blank`; `build.sh` passes `impose.py --pad-before-last` (when `pageMode: single-flowing`, `bookLook: true` and `records/bakside.md` exists), which inserts the mod-4 padding *before* the final page instead of after, keeping bakside page n — the outer sheet's front is `[bakside | forside]`, folding into back and front covers. pypdf is NOT in the hugo-runner image yet: `build.sh` checks `python3 -c 'import pypdf'` and skips only the booklet (stderr note, exit 0) when missing, so enabling the param is safe before the image gains pypdf.

**Content conventions.** The explicit `date:` frontmatter field is authoritative for ordering (`frontmatter.date: [':default', ':filename']`); the filename is only a fallback for records without a `date:` field, so a record's position never depends on its filename. `timeZone: Europe/Oslo` in the site `hugo.yaml` sets the zone for interpreting offset-less dates (front matter and filename timestamps), keeping UTC CI builds on local wall-clock; it's a root config key and Hugo ignores root keys in theme configs (only whitelisted keys like `params` merge), so unlike params the default lives in `hugo.yaml`, not the theme toml; `book.lua` treats dates as naive literals, so PDF/EPUB agree without reading it. All four pageModes order by `.Date` (index modes newest-first; single and single-flowing modes follow `params.singleOrder`, theme default `"asc"` = oldest-first, `"desc"` = newest-first), with `featured: true` records pinned before the rest in every mode — one canonical sort, the inline partial `inline/featured-first.html` in `home.html` (both themes), each group internally per that mode's order. Permalinks use the full `:contentbasename` (time-only slugs would collide across days). Frontmatter flags: `draft: true` (archetype default; kept out of the site), `featured: true` (pinned to top in all four pageModes and the TOC, and in single/single-flowing the block also carries a `featured` class taking a faint accent tint — web only, the PDF/EPUB stay chronological; set by `/stick`), `showDate: false` (hides that page's `.post-date` line in all three render spots; 404.md sets it), `voiceRecorded: true` (accent-coloured mic icon after every Human heading — site and PDF/EPUB). A file named `records/LICENSE.md` gets a footer link (link text = its `title:`, any value; falls back to "License") and is excluded from record lists — both keyed on the filename, not the title. The books include it too: `book.lua` appends the root `LICENSE.md` (non-draft; deeper `LICENSE.md` files stay excluded) as back matter in every mode — an `h2.record-head` titled like the footer link plus a `Div.license` body, placed before a bookLook `bakside` so the back cover stays the last page — giving it a fresh page in the PDF/booklet, its own chapter file and TOC entry in the split EPUB, and a Contents entry in the non-flowing PDF. `tags: [a, b]` renders as dim display-only `#a #b` labels (`.post-tags`, above `.post-date`) in the same three render spots; `params.showTags` (theme default `true`) toggles them site-wide, `showTags: false` opts a page out; taxonomies stay disabled, so tags never become links. `/record #tag Title` (also `/all`, `/me`) files the record under `records/<first-tag>/` with the remaining text as title and all tags in frontmatter; `/stick` resolves slugs folder-aware via `find`. **A record carrying files is a Hugo leaf page bundle** — `<slug>/index.md` with the attachments beside it, published at the byte-identical URL the flat form had (`:contentbasename` resolves a bundle to its folder name); `records attach` does the conversion, `create.new_record(..., bundle=True)` writes one directly, `book.lua` derives the name from the folder rather than `"index"`, and `stick.find_record` matches both shapes. The *rendering* half is theme-split: in single/single-flowing modes every record renders on `/`, so a relative `image.png` 404s under Fuglekasse; Postkasse's `_markup/render-image.html`/`render-link.html` resolve the destination through the page's own resources to a site-root-absolute `.RelPermalink` and so survive those modes (kiste 6, done 2026-08-31). See `docs/attachments.md`. A site-config `cascade` in `hugo.yaml` targets `kind: section` with `build.render/list: never`, so folder URLs like `/linux/` 404 (and no section-template WARN) while records inside keep `/linux/<slug>/` URLs. The 404 page is content: the theme ships `content/404.md` (merged under the site content by Hugo's mounts; a `records/404.md` shadows it). A content file at path `/404` shadows Hugo's standalone 404 kind — that's why the file itself must carry `url: /404.html`, `layout: "404"`, and `build.list: never`, and overrides must keep that front matter block. The built `404.html` is what Codeberg Pages serves for missing URLs. `params.dateTitleFormat` (unset in the theme; the site sets `"02. January 2006"`) renders timestamp-fallback titles as `.Date` formatted with that Go layout — in `page.html`, all three home modes, and the `<title>` tag; hand-written titles are never reformatted. `params.datePostFormat` (unset in the theme; the site sets `"02. January 2006 15:04"`) adds a bottom-right `.post-date` line with the formatted `.Date` to record pages and posts/single-mode cards; unset shows none.

**Logo.** `params.logo` (commented default in the theme toml; the site sets `fuglekasse.svg`) names a file in `static/` rendered as a fixed, non-clickable `<img class="site-logo">` pinned to the viewport's bottom-right corner in `baseof.html` — so it shows on every page. Unset shows none. CSS `.site-logo` lives at the top of `baseof.html` with the other inline styles (Postkasse: `assets/css/postkasse.css`). `params.logoSize` (theme default `"default"`) scales it: `default` 48px, `bigger-1` 60px (+25%), `bigger-2` 72px (+50%), `bigger-3` 96px (+100%) — resolved inline in both themes' `baseof.html` (`warnf` + fallback to `default` on an unknown value) and emitted as a second class `logo-bigger-N` on the `<img>`, never on `default`. The step widths live in a `@media (min-width: 48rem)` block, so phones always render the 48px default; the base `.site-logo` rule is untouched.

**Meta description + OpenGraph.** `_partials/head-meta.html` (both themes; the copies diverged when Postkasse gained the `params.ogCards` block — unlike `render-codeblock-assistant.html`, `comment-link.html`, `head-extra.html`, `static-url.html` and `lang-badge.html`, which stay byte-identical) emits `<meta name="description">` and the OpenGraph block from `baseof.html`, right after `<title>`. It takes a dict `{page, title}`: `baseof.html` now resolves the display title into `$pageTitle` once — the `dateTitleFormat`-on-timestamp-slug rule that used to live inline in the `<title>` tag — and both `<title>` and `og:title` read it, so the rule has one home per theme instead of two. The description is derived at build time rather than hand-maintained, because in `single`/`single-flowing` the front page is the entire search surface and a fixed line goes stale the moment a record is added. Resolution order: the page's own `description:` front matter > `params.description` (home page only; commented default in both theme tomls) > an auto-cut excerpt — the newest record on the home page, the page itself elsewhere. The excerpt takes `.Content`, drops `<pre>…</pre>` (a record opening with a paste would otherwise describe the site with a stack trace), `plainify`s and `htmlUnescape`s it, strips `— model` signature lines and the leading `Human`/`User`/`Assistant` labels the headings leave behind in plain text, collapses whitespace, then joins the first `$words` (14) tokens and appends `...` — trimming a trailing `.,;:`/dash first so the cut never reads `....`. Shorter-than-14-word pages get no ellipsis, and a page with nothing left after stripping gets no tag at all. The newest-record lookup mirrors `home.html`'s chokepoint exactly (LICENSE excluded, `demo` records only while no real record exists), so a fresh demoMode fork describes its demo and stops the moment a real record lands. The OG half emits `og:title`, `og:type` (`website` on the home page, `article` elsewhere), `og:url`, `og:site_name`, `og:locale` (the `lang` attribute's `en-no` re-cased to OG's `en_NO`), `og:description` and `article:published_time` on records; `og:image` comes from `params.ogImage` (commented default, unset = no tag) resolved through `static-url.html` so `cdnURL` applies, then `absURL` because OG images must be absolute. It deliberately does not fall back to `params.logo`: preview crawlers do not render SVG. Hugo's `_internal/opengraph.html` is not used — it would take the description from `.Summary`, which still carries the speaker labels this partial exists to strip. Web-only; the PDF/EPUB carry their own metadata.

**Favicon.** `params.favicon` (commented default in the theme toml; the site leaves it unset) names a `static/` file for the `<link rel="icon">` in `baseof.html` (`or site.Params.favicon "fuglekasse.svg"`, no `type` attribute — the browser sniffs it), falling back to the shipped `fuglekasse.svg` when unset. Kept separate from `logo` because favicons are square and logos are often rectangular.

**Footer repo link.** `params.showRepoURL` (theme default `true`) gates the footer `repoURL` link and the `insidesBranch` branch link in `baseof.html`; `false` hides both. Only display is gated — `repoURL` still rewrites relative `records/` links (record.html, book.lua), and CI keeps injecting `HUGO_PARAMS_REPOURL`, so forks that don't want the link set `showRepoURL: false` rather than emptying `repoURL`. When `repoURL` resolves to nothing (no config, no CI env — e.g. plain local builds), the footer link and the record.html rewrite are both skipped (book.lua already guarded). Set it in `hugo.yaml`, not via `HUGO_PARAMS_SHOWREPOURL` — env values are strings and `"false"` is truthy.

**Forge links.** `params.repoLinkStyle` (theme default `auto`) picks the raw/browse URL shape for `repoURL`-based links: `auto` = github.com → GitHub (`/raw/<b>/`, `/tree/<b>`), gitlab.com → GitLab (`/-/raw/<b>/`, `/-/tree/<b>`), anything else → Forgejo/Gitea (`/raw/branch/<b>/`, `/src/branch/<b>`); explicit `forgejo|github|gitlab` overrides (unknown values `warnf` + forgejo — needed e.g. for self-hosted GitLab). `params.repoBranch` (theme default `main`) replaces the previously hard-coded `main`. Resolution lives in `_partials/repo-link.html` (takes `{kind: "raw"|"tree", branch?}`; `record.html` uses raw, the `baseof.html` `insidesBranch` link uses tree with the branch override) and is mirrored in `book.lua` (`rawPrefix`). Defaults reproduce the old Codeberg output byte-for-byte.

**The engine's commands.** `recordkit/cli.py` exposes 27 subcommands. The original twelve (`new`, `append`, `append-turn`, `ollama-reply`, `ollama-chat`, `stick`, `commit`, `publish`, `myname`, `mucke`, `werden`, `config`) plus `airtime` back the skills; fourteen more came from the roadmap roads and have no slash-command counterpart: `import` (suitcase — `claude-code`/`llm`/`markdown` parsers, idempotent via the `source:`+`sourceId:` frontmatter pair), `archive`/`verify`/`export`/`attach` (schrank — deterministic zip + SHA-256 manifest, checksum and reference checking, plain-text export, leaf-bundle attachment), `pack` (portaloo — post-processes `public/` into one offline HTML file; requires `pageMode: single` or `single-flowing`, never builds), `card`/`booth` (booth — one turn as a 1200×630 SVG in the site's palette, and a stdlib-curses composer that writes through `create.py`/`writer.py` like every other path), `doctor`/`watch` (hundehus), `redact`/`unpublish` (utedo — a shown-diff seam rewrite that never touches git, and `draft: true`-based withdrawal with a tombstone and `--restore`), and `scan`/`ignore` (utedo — masked credential-shape findings, and the `.recordsignore` → `ignoreFiles` translator). **`doctor`, `watch`, `scan` and `ignore` are the exceptions to JSON-on-stdout**: they own their flags and their human-readable rendering, so `main()` dispatches them through the `_PASSTHROUGH` map straight to the module's own `main()` before the main parser runs — `argparse.REMAINDER` cannot carry leading options through a subparser, which is why the interception happens first. Adding a road command means a module plus a subparser plus a dispatch branch; while several road sessions run in parallel the registration is deferred and wired in one pass afterwards (the rule lives in `docs/records/developers/roadmap/README.md`).

**Publishing.** `bin/build.sh` is the one build path for every provider (URL ladder above under Layout). The CI shims stay logic-free and each guards its own host: `.forgejo/workflows/pages.yml` (guard: codeberg.org or `vars.PAGES_HOST` set; `runs-on`, build-step `PAGES_HOST` env and git-pages `server:` fall back from the instance Actions vars `PAGES_RUNNER`/`PAGES_HOST` to the Codeberg defaults, so a self-hosted Forgejo running git-pages publishes zero-edit once its admin sets the two vars — first such instance: g.xil.no → p.xil.no; three more optional instance vars cover in-cluster runners: `PAGES_SERVER` (internal deploy target — the Derive-deploy-URL step flips the site URL to plain `http://` for the request, and `server:` prefers it), `FORGE_URL` (public forge URL, fed to build.sh for repo-link derivation when the runner-side `GITHUB_SERVER_URL` is internal) and `RUNNER_IMAGE` (job container override); a fourth, `PAGES_ACTION`, points the deploy step's `uses:` at an instance-local mirror of the git-pages action via a Forgejo-evaluated expression (fallback: `codeberg.org/git-pages/action` upstream — Forgejo, unlike GitHub, evaluates `${{ }}` in step `uses`); the action is fed `env.DEPLOY_URL`), `.github/workflows/pages.yml` (`github.com` guard — Forgejo/Gitea read `.github/workflows` as a fallback; `configure-pages` `base_url` → `BASE_URL`; official pages-artifact flow), `.gitlab-ci.yml` (`hugomods/hugo:debian-0.164.0` — the `debian-exts` tag line died at 0.154.5, which predates the theme's `site.Language.Locale` (Hugo ≥ 0.158) — classic `pages` job, `CI_PAGES_URL` read inside build.sh). No-CI delivery is `records publish` (see the `tools/others/` bullet); its params (`publishTarget`, `publishBranch`, `publishRemote`, `publishDest`) ship commented in `hugo.yaml` next to `deployCommand`, and they are tooling params — templates never read them. User docs + fork migration notes: `docs/publish.md`.

**Syntax highlighting.** `hugo.yaml` sets `markup.highlight.noClasses: false`, so Chroma emits token *classes* instead of inline colours. `baseof.html` styles them with `--hl-*` CSS variables that flip on `prefers-color-scheme` (light = Tokyo Night Light, dark = Dracula, matching `params.style`). The `.chroma` wrapper stays transparent, so code keeps the `pre`/`--surface` background in both modes. Add new token colours by extending the `--hl-*` vars, not per-language rules.

**Generator meta.** `hugo.yaml` sets `disableHugoGeneratorInject: true` and a `module.mounts` entry mounting the repo-root `CURRENT` into `assets/CURRENT` (Hugo's `readFile` can't leave the project dir; the legacy `contentDir`/`staticDir`/`dataDir` keys coexist with the mount). Both themes' `baseof.html` emit `<meta name="generator" content="blyant records <version>">` on every page — `<version>` is the first field of `CURRENT` via `resources.Get "CURRENT"`, `with`-guarded so a missing file just drops the tag. Nothing to bump on werden turns: the tag reads `CURRENT` at build time.

**Deliberate omissions.** RSS and taxonomies are disabled in `hugo.yaml` — the embedded RSS template would leak signature lines through summaries. Goldmark `unsafe: true` is intentional (records are trusted first-party content).

## Conventions

- Keep the theme minimal: flat templates, a handful of partials, inline CSS, no build tooling. Resist adding partials, JS, or asset pipelines.
- `records/` markdown is user content — don't edit records except via the skills or on explicit request.
- Never commit or push unless explicitly asked.
- The werden cycle (`CURRENT` + `/werden`) is human-triggered — agents never run it unprompted.
