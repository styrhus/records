1. INTRODUCTION                                          *records-introduction*

records.nvim is the Neovim front end for blyant records — a publish-your-
conversations site where every record is a Markdown file in your own repo.

The plugin holds no logic of its own. Every action shells out to the `records`
CLI (recordkit), which does the frontmatter, the naming, the git work and the
publishing. If Neovim needs something the CLI cannot do, the CLI grows, not
this plugin.

==============================================================================
2. REQUIREMENTS                                          *records-requirements*

The recordkit CLI, installed separately: >

    pipx install recordkit
<
Neovim 0.9 or newer. No Lua dependencies.

==============================================================================
3. INSTALLATION                                          *records-installation*

The plugin ships inside the records repository rather than as its own repo, so
install it by path. With lazy.nvim: >

    {
      "records.nvim",
      dir = "~/path/to/records/tools/others/neovim",
      cmd = "Records",
      config = function()
        require("records").setup({ bin = "records" })
      end,
    }
<
With packer.nvim: >

    use { "~/path/to/records/tools/others/neovim" }
<
Or copy it onto your runtimepath: >

    cp -r records/tools/others/neovim \
      ~/.local/share/nvim/site/pack/manual/start/records
<
setup() is optional — |:Records| works unconfigured.

==============================================================================
4. CONFIGURATION                                        *records-configuration*

                                                              *records.setup()*
require("records").setup({opts})

    {opts} keys, with their defaults:

    bin              string   "records"
                     The recordkit CLI to run. Set it to an absolute path if
                     `records` is not on Neovim's PATH.

    ollama_endpoint  string   nil
                     Ollama base URL, e.g. "http://localhost:11434". Unset
                     (or empty) disables Ollama entirely — every command
                     stays mechanical.

    ollama_model     string   nil
                     Model tag for ollama_endpoint, e.g.
                     "qwen2.5-coder:latest". Required alongside
                     ollama_endpoint; without it /record records user-only
                     and says so.

    stream           boolean  false
                     Token-by-token replies via `records ollama-reply/-chat
                     --stream`. Off by default: that flag is not wired into
                     the shared cli.py yet. Turning this on before it lands
                     makes every Ollama turn fail the same way an
                     unreachable endpoint does — gracefully, with the
                     human's words still appended user-only.

5. COMMANDS                                                  *records-commands*

                                                                    *:Records*
:Records        Open the chat panel at the bottom of the editor. Type a
                message or a /command and press <CR> in insert mode. Press
                `q` in normal mode to close the panel.

==============================================================================
6. CHAT COMMANDS                                        *records-chat-commands*

Typed into the panel. They mirror the VS Code sidebar and the AI skills one
for one.

    /record [#tag] [title]   Start recording (user-only in Neovim today)
    /all [#tag] [title]      Start a user-only recording
    /me [#tag] [title]       Start a draft recording, kept off the site
    /esc                     Stop recording
    /stick <slug>            Feature a record
    /gc [message]            Commit
    /gcp [message]           Commit and push
    /cpd [message]           Commit, push, deploy
    /myname [name]           Save your name locally
    /mucke                   Stamp the now-playing track into the record
    /airtime                 Human vs Assistant token share of the record
    /config                  Show the resolved records directory

A plain message, while a recording is active, is appended to it verbatim as a
Human turn. With no recording active, nothing is written.

The first word of a /record, /all or /me title may be a #tag; the record is
then filed under that tag's folder. Tags and spaces are passed to the CLI as a
single argument, never through a shell.

==============================================================================
7. OLLAMA                                                      *records-ollama*

A local Ollama model is optional everywhere in this project. With
ollama_endpoint and ollama_model both set: >

    require("records").setup({
      ollama_endpoint = "http://localhost:11434",
      ollama_model = "qwen2.5-coder:latest",
    })
<
/record becomes a real two-sided turn. Your line is sent to
`records ollama-reply --endpoint … --model … --file … --human …`, run as a
background job so typing more never blocks on the model; the reply is
appended to the record and signed with the model tag. The endpoint and model
are captured when the recording starts and held for its whole session —
changing settings mid-recording changes nothing until the next /record.

A failed or unreachable model degrades to exactly what /all would have
written: your words are still appended, mechanically, and a warning explains
why there is no reply. Nothing is ever lost — the CLI never writes a record
when generation fails, so there is nothing to lose in the first place.

Without an active recording, and with a model configured, a plain message
becomes an ephemeral chat via `records ollama-chat` instead — the same turn
the VS Code sidebar offers when nothing is being recorded. Nothing from an
ephemeral chat is ever written to disk. /esc clears both the recording and
the ephemeral chat's history.

Set `stream = true` for token-by-token replies instead of one message landing
all at once. It is off by default: streaming needs a `--stream` flag on
`ollama-reply`/`ollama-chat` that the shared CLI does not have yet. Until it
does, turning this on does not break anything — a turn made with --stream
against a CLI that doesn't understand it fails exactly like an unreachable
model does, appending the human's words user-only.

==============================================================================
8. WATCH                                                        *records-watch*

`records watch` (see the hundehus road in this repo's roadmap) is a separate,
long-running process that rebuilds the site when a record changes. It is
started and read independently of the chat panel:

                                                              *:RecordsWatch*
:RecordsWatch          Start `records watch --json` in the background.

                                                          *:RecordsWatchStop*
:RecordsWatchStop      Stop it.

                                                        *:RecordsWatchStatus*
:RecordsWatchStatus    Show the watcher's status — running or not, and the
                        last build's outcome — via |vim.notify|.

                                                *records.watch_status()*
require("records").watch_status()
                        The same status line as :RecordsWatchStatus, as a
                        string, for building your own statusline component.

`records watch` writes no state file of its own; status comes from the
`--json` events the plugin's own watch process emits on stdout, not from
anything read out of `recordkit/watch.py`. The watcher never commits, pushes
or publishes — this plugin only ever reads what it reports.
